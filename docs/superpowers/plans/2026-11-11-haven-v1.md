# Haven v1 Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) tracking. Execute in
> order; each task ends with a green test and a commit. Requirements come from
> `docs/00-VISION.md` … `docs/07-ROADMAP.md`.
>
> **For parallel work:** tasks marked `[∥]` touch disjoint files and may run in
> separate worktrees. Tasks marked `[!]` change shared interfaces — do them
> serially on `main`, then rebase the parallel worktrees.

**Goal:** a working Haven platform — vendor defines a product, firmware claims
itself, customer pairs by radar and controls the device.

**Architecture:** two Rust binaries (`haven-api`, `haven-worker`) over a
feature-sliced `domain` crate, Postgres with RLS tenancy, VerneMQ as the
device bus, Expo app and React portal generated from the emitted OpenAPI.

**Tech stack:** Rust 1.99 · axum 0.8 · sqlx 0.8 · tokio · rumqttc · utoipa ·
Postgres 16 (partitioned) · Valkey 8 · VerneMQ 2 (Apache-2.0) · Expo 58 · React 19 + Vite 7.

## Global constraints

- Edition 2024, `#![forbid(unsafe_code)]` in every crate except `sdk/`.
- No `unwrap`/`expect`/`panic!` outside `#[cfg(test)]` and `main`.
- Every public API route returns the error envelope `{error:{code,message}}`.
- Timestamps are UTC; ids are UUIDv7.
- All tenant tables carry `vendor_id` and an RLS policy.
- Formatting: `cargo fmt` + `clippy -D warnings` + `prettier` in CI.

## Review focus (the five that will bite)

1. A claim that retries after a Wi-Fi drop must not create a second device.
2. A command that times out must settle `timeout`, never stay `queued`.
3. A vendor must not read another vendor's device by guessing an id.
4. A device report for a point the product does not declare must be dropped,
   and the client must still see the rest of the report.
5. An app reconnect must not resurrect stale values — refetch on reconnect.

- [ ] Test: a thing model that maps `brightness` without `switch` for `category:light` fails rule 6.
- [ ] Implement; `cargo test -p protocol`.

## Task 9 — Pairing and claim `[!]`

**Files:** `domain/src/pairing/*`, `api/src/routes/provision.rs`

- [ ] Ticket minting (admin), 5 min TTL, Ed25519 signed, single use.
- [ ] `POST /provision/claim`: verify secret (Argon2id), ticket signature, vendor

  sign the CSR; return cert + MQTT config; publish `device.added`.
- [ ] Test: replaying the same `(sn, ticket)` twice within 10 min returns the
  same device id and creates no second row.
- [ ] Test: an expired ticket returns `400 ticket_expired` and no device.

## Task 10 — MQTT ingest and shadow `[!]`

**Files:** `worker/src/{ingest,shadow,main}.rs`

- [ ] Test: a report with one known and one unknown dp updates one point and
